# ProtoCarry v0.1.0

ProtoCarry's first release checks whether an older application preserves selected newer Protobuf fields through its real read/write path.

- Standalone Go CLI with `check` and saved-input `replay` commands.
- User-provided descriptor sets, binary seeds and executable adapters using stdin/stdout.
- Deterministic cases for added proto3 scalar, string, bytes, optional and bounded singular message fields.
- Independent comparison of values and explicit presence against the newer schema.
- Per-case outcomes and reproducible evidence, including binary inputs/outputs, descriptors, assertions, runtime metadata and artifact hashes.
- Examples of binary preservation, mapper loss, ProtoJSON loss and permitted application mutations.

External validation reproduced protobuf.js 8.6.1 default preservation, 8.6.2/8.8.0 default loss, and preservation with `reader.discardUnknown = false`. The official Go runtime is a positive control. The measurements apply to the tested runtime versions, options and preservation contract.

Binary archives are provided for macOS arm64 and Linux arm64, with SHA-256 checksums. They include the standalone CLI, README and MIT license. Node.js, protoc and Buf are not required to run the binary.

The supported model excludes proto2, Editions, extensions, enum semantics, real oneofs, repeated/map traversal and incompatible changes to existing fields. PASS applies only to the saved contract and executed cases. Process cleanup is supported on macOS and Linux; it is not a sandbox for arbitrary adapters.

See the [README](../../README.md) for configuration, adapter examples, outcome meanings and replay instructions.
