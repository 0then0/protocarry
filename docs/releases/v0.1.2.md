# ProtoCarry v0.1.2

This release adds project documentation and a second external library compatibility case. The check logic, supported schema model, configuration format and stdin/stdout adapter protocol are unchanged.

## Kotlin/JVM compatibility case

The new [kotlinx.serialization case](../../validation/kotlin-serialization/README.md) runs a small Kotlin adapter through ProtoCarry in three modes with the same descriptors, seed and contract:

- No `ProtoUnknownFieldHolder`: FAIL. The added root field and the added field inside the known nested message are lost; controls are preserved.
- Holder carried through the read/write path: PASS for both fields.
- A mapper that rebuilds the object from known properties: FAIL with the same two lost fields.

The case records representative evidence and replays it offline. It was measured with kotlinx.serialization 1.12.0, Kotlin 2.4.10 and JDK 17. It is an external library compatibility case, and the first and third results are not library defects. A JDK and Gradle are needed only under `validation/kotlin-serialization`; the CLI remains a standalone Go binary.

## Evidence compatibility

Replay accepts format `2` evidence produced by `0.1.1` and by `0.1.2`, and format `1` evidence produced by `0.1.0`. Other producer and format combinations are still rejected before adapter execution. New evidence is written in format `2`.

## Other changes

- Contributor, conduct and security policies, issue and pull request templates and shared editor settings.
- Explicit LF text handling that preserves binary descriptor and evidence bytes.
- CI cancels superseded runs and has time limits. A separate job runs the Kotlin case.
- Refreshed project icon.

Release targets remain macOS arm64 and Linux arm64, with standalone binary archives and SHA-256 checksums. See the [contract reference](../contract.md) for configuration and replay rules.
